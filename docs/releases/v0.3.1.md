# vram-mcp 0.3.1

A packaging fix for 0.3.0. Install this instead of 0.3.0; nothing else changes,
and the [0.3.0 notes](v0.3.0.md), including its upgrade requirements, still
apply.

```sh
uvx --from git+https://github.com/sushiHex/vram-mcp@v0.3.1 vram-mcp
```

## Fixed

- **0.3.0 could install a server that crashes at startup.** It declared
  `mcp>=1.10`, but every `mcp` release before 1.21.1 imports a private pydantic
  function that current pydantic no longer has. A resolver that settled on one
  of those releases produced `ImportError: cannot import name
  'eval_type_backport'` when the server started. The floor is now
  `mcp>=1.21.1`.

  It surfaced through `uvx` on Windows with a free-threaded Python. Every `mcp`
  release from 1.11 on requires `pywin32` there, and `pywin32` publishes no
  free-threaded wheels, so `uv` fell back to `mcp 1.10.1`. With the corrected
  floor, that environment now fails to install with an error that says why;
  see *Free-threaded Python on Windows* below.

## Changed

- CI now also tests the direct dependencies at the lowest versions they resolve
  to on Python 3.10, so a floor that no longer works fails a build instead of a
  user.
- The server tests no longer skip when `mcp` cannot be imported. It is a
  required dependency, and skipping is how a broken SDK could pass CI quietly.

## Free-threaded Python on Windows

The MCP SDK requires `pywin32` on Windows, which has no free-threaded build. If
`uv` selects a free-threaded interpreter (`3.14t`), pin a standard one:

```sh
uvx --python 3.13 --from git+https://github.com/sushiHex/vram-mcp@v0.3.1 vram-mcp
```
